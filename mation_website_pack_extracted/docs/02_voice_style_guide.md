# 02 — Voice & style guide

## Writing rules

- Use short sentences.
- Prefer concrete nouns: “workflows, approvals, audit trails” over “synergy.”
- Every claim should imply *how it’s achieved* (even briefly).
- Avoid “AI will change the world” style lines.

## Tone

- Confident, not arrogant.
- Direct, not salesy.
- Technical pages should read like a great architecture doc: clear boundaries, clear intent.

## Vocabulary (preferred)

Use:
- operating system, operating layer
- orchestration, workflow, actions
- audit trail, evidence-backed
- modular, reusable components
- tool gateway, permissions, approvals
- chat-first, not chat-only
- generative interface / generated UI

Avoid:
- “revolutionary”, “disruption”, “game-changing” (unless immediately substantiated)
- “magic” (use once at most, and only as a contrast)
- “AGI”, “superintelligence” on the marketing site (unnecessary friction)
